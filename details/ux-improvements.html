CASE 01 · Product design · Public case note

잘못된 UX 설계,
14가지 개선안을 제시했습니다.

UX 문제를 자발적으로 리서치해 14개의 개선안을 만들고 제안했습니다. 대형 서비스를 Reference로 근거를 정리하고, 기획팀·디자인팀·백엔드와 적용 범위를 조율했습니다. 채택된 안은 Before·After 시안과 명세를 바탕으로 API Response, 기획서, 디자인을 함께 갱신하고 구현까지 연결했습니다. 이 문서는 포트폴리오의 결과 요약보다 UX 판단과 팀 협업 과정을 자세히 기록한 문서입니다.

  • Proposal14개 개선안
  • Adoption12개 채택
  • Scope5개 Page + 공통 Navigation
Starting point

방문 대비 Core Action 전환율이 낮다는 사실을 확인했습니다.

문제를 인식하게 된 첫 번째 계기는 일간 방문자 수에 비해 사용자의 Core Action 전환율이 낮았다는 점입니다.
서비스를 직접 개발하며 느낀 UX 불편도 있었고, 베타 서비스 피드백에서 “사용하기 편했나요?”라는 질문의 평점이 5점 만점에 2.5점에 그친 것도 사용성에 문제가 있다는 신호로 받아들였습니다.
이 내용을 확인한 뒤, 프로덕트에 도움이 되는 방향이라면 직접 나서는 게 맞다고 판단해 리서치와 개선안 작성을 시작했습니다.

01 · User observation

사용자가 Core Action까지 이어지는 흐름을 관찰했습니다.

리서치 과정에서는 대형 서비스의 UX와 인플루언서들의 타서비스 이용 방식을 참고했습니다.
추가적으로 이벤트 로그를 통해 사용자가 Core Action 페이지에 도달하지 못한 것인지, 도달했지만 액션으로 이어지지 않은 것인지 나누어 확인했습니다. 분석 결과 Core Action 페이지에 도달하지 않은 사용자가 적지 않았고, 특히 모바일 접속자에서 이 현상이 두드러졌습니다. 모바일 접근 UX 개선을 우선 과제로 판단했고, 같은 이용 흐름을 데스크톱에서도 더 명확하게 정리할 필요가 있다고 보았습니다.
익숙한 UX 패턴을 바탕으로 사용자가 편안함을 먼저 느끼게 하고, Core Action까지 이어지는 사용자의 행동을 정의하는 데 초점을 맞췄습니다. 그 결과 각 화면에서 달성해야 할 UX 방향도 분명해졌습니다. Home에서는 더 많은 Market을 비교한 뒤 다음 선택으로 이어질 수 있어야 했고, 이동 과정에서는 관심 범위를 좁혀도 탐색 맥락을 유지해야 했습니다. 거래 화면에서는 거래 방식에 맞는 정보로 Core Action을 시작할 수 있어야 했습니다.

Step 01 · Read information

더 많은 Market을 한 번에 비교할 수 있어야 합니다.

대형 서비스의 UX와 타서비스 이용 방식을 참고하며, 첫 화면에서 다양한 대상을 빠르게 비교하고 다음 선택으로 이어지는 구조가 중요하다고 판단했습니다.

  • 첫 화면에서 다양한 Market을 빠르게 비교할 수 있는 밀도
  • 탐색 대상이 시각 요소보다 먼저 보이는 정보 계층
  • 관심 대상을 찾은 뒤 다음 행동으로 이어지는 구조
Step 02 · Explore

관심 범위를 좁혀도 탐색의 맥락이 이어져야 합니다.

사용자가 보고 싶은 범위를 선택한 뒤에도 현재 무엇을 찾고 있는지 잃지 않고, 필요한 화면으로 자연스럽게 이동할 수 있어야 한다고 보았습니다.

  • 관심 범위를 선택적으로 좁힐 수 있는 진입
  • 페이지 이동 후에도 선택 기준을 잃지 않는 흐름
  • 자주 이동하는 메뉴와 전체 메뉴의 역할 구분
Step 03 · Start action

거래 방식에 맞는 정보로 Core Action을 시작할 수 있어야 합니다.

Core Action을 시작하는 순간에는 사용자가 현재 선택한 거래 방식과 필요한 입력을 바로 이해할 수 있어야 한다고 정리했습니다.

  • 거래 방식에 따라 필요한 입력 정보를 구분
  • Core Action 전에 확인해야 할 정보의 우선순위 정리
  • 필요한 입력을 이해한 뒤 바로 Action으로 이어지는 흐름
02 · Problem definition

사용자가 Core Action에 도달하는 과정과, 그 과정 중 불편하거나 익숙하지 않게 느낄 지점을 정의했습니다.

리서치를 통해 수집된 정보를 각 화면의 AS-IS로 정리하였습니다.

Scope AS-IS
Header Header 안에 Core Action과 직접 연결되지 않는 요소가 섞여 있음
  • Core Action에 사용되지 않는 메뉴가 Header에 배치되어 주요 정보와 행동으로 시선이 분산됨
  • Account 영역을 클릭하면 큰 Dropdown이 열려 콘텐츠를 가리고 불필요한 영역을 차지함
  • 사용자의 Hedging 현황을 정확하게 확인할 수 있는 Content가 없음
Sidebar 메뉴의 우선순위와 배치 순서가 맞지 않음
  • 사용자가 자주 이용하는 주요 메뉴가 Sidebar 하단에 배치됨
  • 사용 빈도가 낮거나 당장 필요하지 않은 메뉴가 상단에 노출됨
  • 메뉴의 역할과 이동 우선순위를 한 번에 파악하기 어려움
Home 탐색해야 할 Market보다 시각 요소의 주목도가 높음
  • 큰 Banner와 Card가 실제로 비교해야 할 Market보다 크게 보임
  • 반복 가격 정보가 화면의 많은 영역을 차지함
  • 한 화면에서 비교할 수 있는 Market의 수가 적음
Category 관심 범위를 좁혀 볼 방법이 없음
  • Home에서 많은 Market을 볼 때 Category 기준으로 필터링할 수 없음
  • 관심 있는 범위만 골라 확인하려면 전체 목록을 직접 탐색해야 함
  • Market을 확인한 뒤 이전 탐색 범위를 유지할 기준이 없음
Market 거래 방식에 따라 필요한 정보와 불필요한 Input이 함께 노출됨
  • 서로 다른 입력 방식에 필요한 조건이 다른데도 같은 영역에서 함께 다뤄짐
  • 서비스 이용에 필요하지 않은 Input 영역이 너무 많이 노출됨
  • 무엇을 먼저 확인하고 입력해야 하는지 거래 시작 전에 다시 판단해야 함
Portfolio 포트폴리오 내 주요 정보의 우선순위가 잘못 정리됨
  • 처리 중 금액·수령 가능 금액·기간 정보가 주요 보유 내역보다 먼저 시선을 차지함
  • Table에서 한 번에 확인할 수 있는 정보가 제한적임
  • 자세한 내용을 모두 확인하려면 Table 항목을 클릭해 Modal을 열어야 함
Profile Profile Content의 역할과 이용 경로가 분명하지 않음
  • Profile에서 확인할 활동 정보와 Portfolio의 보유 내역이 분리되어 있음
  • Portfolio와 유사한 정보를 다루지만 두 화면의 Content 차이가 명확하지 않음
  • Profile에서 확인한 정보가 다음 탐색이나 행동으로 자연스럽게 이어지지 않음
03 · Improvements

익숙한 UX 패턴을 바탕으로, Core Action까지의 개선안을 제안했습니다.

이번 문서가 다루는 14개 개선안을 항목별로 나누어 AS-IS와 TO-BE를 함께 기록했습니다. 아래 Screen은 대표 사례가 아니라 각 제안의 변경 내용과 반영 여부를 보여줍니다.

Scope TO-BE 제안 이유 · 기대 효과
Header Account Dropdown 개편Account 영역을 유지하되 Dropdown의 크기와 메뉴를 핵심 기능 중심으로 조정합니다. 계정 메뉴가 핵심 화면을 가리지 않고, 사용자가 필요한 기능을 더 빠르게 찾을 수 있습니다.
Header Header 상태 정보 추가Header에서 Cash와 Hedging 금액을 함께 확인할 수 있는 Content를 추가합니다. 핵심 화면으로 이동하기 전에 현재 상태를 확인하고 다음 행동을 판단할 수 있습니다.
Sidebar Sidebar 메뉴 재배치자주 사용하는 주요 메뉴를 앞쪽으로 이동하고, 필요성이 낮은 메뉴는 하단으로 배치합니다. Sidebar에서 자주 이용하는 메뉴를 먼저 찾고, 메뉴의 역할과 이동 우선순위를 쉽게 이해할 수 있습니다.
Mobile Navigation 모바일 UX 보완Mobile 환경에서도 원활한 UX를 제공하기 위해 자주 이동하는 메뉴를 Bottom Navigation으로 추가합니다. 모바일에서도 서비스 내 이동을 쉽게 하고, Header·Bottom·Sidebar 각 Navigation의 역할을 구분할 수 있습니다.
Home 카드 밀도와 계층 조정한 줄에 보이는 Market 수를 늘리고, 제목·폰트·가격 영역을 줄입니다. 한 번에 더 많은 Market을 비교해 정보 밀도를 높일 수 있습니다.
Category 선택형 Category Filter 추가필요할 때만 Category를 선택하고, 선택한 범위를 히스토리 엔트리에 저장해 뒤로가기 이후에도 유지합니다. 사용자가 관심 범위를 좁혀 Market을 비교하고, Back 이후에도 같은 범위에서 탐색을 이어갈 수 있습니다.
Market 입력 방식별 정보 축소선택한 입력 방식에 따라 세부 Input 항목을 감추고, 현재 방식에 필요한 정보만 노출합니다. 현재 선택한 입력 방식에서 무엇을 확인하고 입력해야 하는지 바로 이해할 수 있습니다.
Market Market Tab 구조 개편상세 정보와 활동 영역을 Tab으로 나누어 필요한 Content를 바로 확인할 수 있게 합니다. 한 화면을 계속 탐색하지 않고, 목적에 맞는 정보 영역으로 바로 이동할 수 있습니다.
Market Rules Content와 UI 개편Rules의 내용과 표현 방식을 다시 구성해 긴 설명도 읽기 쉬운 순서로 제공합니다. 핵심 정보를 먼저 확인하고, 필요한 경우 상세 조건까지 이어서 읽을 수 있습니다.
Portfolio Portfolio 요약 정보 개편현재 자산과 보유 내역의 우선순위를 다시 정리해 요약 영역을 구성합니다. Portfolio에 들어온 직후 현재 상태와 주요 금액을 먼저 파악할 수 있습니다.
Portfolio Portfolio Table 디자인 개편Table에서 더 자세한 내용을 한 번에 보여주고, 별도 클릭이나 Modal 진입 없이 주요 정보를 비교할 수 있게 합니다. 현재 가진 자산과 보유 내역을 먼저 확인하고, 필요한 후속 Action을 찾을 수 있습니다.
Profile Profile Page의 Content 수정Portfolio와 유사한 정보를 다루되, Profile의 Content 구성과 보여주는 정보를 다르게 정리합니다. 기본 정보와 활동 내역을 하나의 이용 흐름에서 확인할 수 있습니다.
Market · 미반영 Market 검색 기능 추가사용자가 원하는 Market을 직접 찾을 수 있는 검색 기능을 제안했습니다. 당시 Backend에는 검색 엔진 관련 기능이 없었고 개발 인력도 부족해, 검색 기능 대신 Category Filtering을 대안으로 제안했습니다.
Profile · 미반영 Profile과 Settings 통합Settings는 별도 페이지로 두기에는 Content가 많지 않았고, Profile이 Portfolio와 유사한 기능을 제공하고 있어 통합을 제안했습니다. 기획팀·디자인팀과 논의한 결과, 향후 Settings Content가 추가되면 다시 별도 페이지로 분리될 수 있어 통합안을 반려했습니다.
Screen 01 · Header Account

Account Dropdown의 크기와 메뉴를 조정했습니다.

Header의 Account 영역은 유지하되 Dropdown이 핵심 화면을 가리지 않도록 크기를 줄이고, 자주 사용하는 계정 기능을 중심으로 메뉴를 정리했습니다.

AS-ISlarge dropdown
Account큰 Dropdown · 메뉴 혼재
TO-BEfocused menu
Account핵심 메뉴 중심 Dropdown

핵심 변화: Account 영역은 유지하면서 Dropdown의 시각적 무게를 줄여 핵심 화면을 가리는 영역을 덜어냈습니다.

Screen 02 · Header status

Header에서 Cash와 Hedging 금액을 바로 확인하게 했습니다.

기존 Header에는 Markets와 Account만 있어 사용자의 현재 상태를 확인하려면 다른 화면으로 이동해야 했습니다. Core Action 전에 필요한 상태 정보를 Header에 추가했습니다.

AS-ISstatus missing
HeaderMarkets · Account
상태 정보별도 Content 없음
TO-BEstatus visible
HeaderMarkets · Cash · Hedging · Account
상태 정보Cash · Hedging 금액

핵심 변화: 핵심 화면으로 이동하기 전에 Cash와 Hedging 금액을 확인하고 다음 행동을 판단할 수 있게 했습니다.

Screen 03 · Sidebar

Sidebar 메뉴를 사용 빈도와 역할에 따라 재배치했습니다.

Sidebar에는 전체 메뉴가 들어가 있었지만, 주요 메뉴가 아래에 있고 필요성이 낮은 메뉴가 위에 배치되어 있었습니다. 사용자가 자주 이동하는 영역을 먼저 찾을 수 있도록 메뉴의 순서와 역할을 다시 정리했습니다.

TO-BEpriority first
상단주요 메뉴
하단필요성이 낮은 메뉴
역할이동 우선순위 명확

핵심 변화: 모든 메뉴를 유지하되 사용 빈도와 역할에 따라 순서를 조정해, Sidebar를 열었을 때 다음 이동을 더 쉽게 판단할 수 있도록 했습니다.

Screen 04 · Mobile Navigation

모바일에서도 서비스 내 이동을 쉽게 이해하도록 보완했습니다.

AS-IS에는 Bottom Navigation이 없었고, 모바일에서도 Header와 Sidebar를 통해 메뉴를 찾아야 했습니다. 자주 이동하는 영역을 Bottom Navigation으로 분리해 모바일 환경에서 Navigation의 역할을 구분할 수 있도록 했습니다.

핵심 변화: Header와 Sidebar의 역할은 유지하면서 자주 이동하는 영역을 Bottom Navigation으로 분리해 모바일에서도 이동 경로를 빠르게 파악할 수 있게 했습니다.

Screen 06 · Category

04 · Results

팀과 협업해 제안의 반영 범위와 구현 방향을 결정했습니다.

14개 개선안은 먼저 기획팀의 1차 검토를 거쳤고, 이 단계에서는 큰 수정 없이 그대로 진행하는 것으로 확인됐습니다. 이후 일부 화면에는 개선 방향을 실제로 먼저 적용해 Before·After를 직접 비교할 수 있게 했고, 이를 반영한 Before·After 비교 페이지를 만들어 팀 미팅에서 발표했습니다. 미팅에서 나온 질문은 대부분 프론트엔드 UI, 디자인팀 Figma, 기획팀 기획서 변경이 각각 얼마나 필요한지에 관한 것이었습니다. 디자인팀은 이미 검토했던 UX와 겹치는 안에 실제 효과와 목적을 확인하는 질의를 더했고, 기획팀은 1차 검토를 마친 상태라 추가 질의는 없었습니다. 이 논의를 거쳐 Market 검색 기능과 Profile·Settings 통합 2건은 반려되고, 나머지 12개 제안이 채택됐습니다.

채택된 12개의 제안에 대해서는 추후 Data, Edge Case, 사용자 시나리오 등을 보강하여 구현했습니다. 개발 과정에서는 백엔드와 협업하여 API Response를 변경하고, 기획팀·디자인팀과 협업하여 제안서를 바탕으로 기획서와 디자인을 갱신했습니다.
